# UI 设计与开发规范

本文档定义 Construction Project Accounting 桌面端的 UI 设计原则、组件约束和验收标准。适用于 `src/gui/` 及 `src/gui/qt/` 下的新增功能和界面改造。

> 根目录 `AGENTS.md` 中的规则属于强制开发约束。若本文档与 `AGENTS.md` 冲突，以 `AGENTS.md` 为准。

## 1. 规则等级

本文使用以下等级区分规则的成熟度：

- **必须**：已有基础设施或自动化测试支持，新增及修改代码必须遵守。
- **推荐**：新界面优先遵守，旧界面在改造时逐步迁移。
- **规划中**：设计方向已经明确，但公共令牌、组件或测试仍待实现。

不要把“规划中”的内容当作已经存在的公共 API。实现新令牌或公共组件后，应同步更新本文档和相应测试。

## 2. 设计原则

### 2.1 一致性（必须）

颜色、字号、图标、Tooltip 和通用交互应从统一入口获取。功能模块只消费公共能力，不自行建立另一套视觉规范。

### 2.2 清晰优先（推荐）

界面应优先保证信息层级、可读性和操作反馈，不使用无业务含义的装饰元素。相同动作在不同页面应使用一致的名称、图标和位置。

### 2.3 渐进升级（推荐）

避免为统一外观而一次性重写全部界面。新增页面必须遵守本规范；修改旧页面时，应顺带迁移本次涉及的区域，并保持数据格式和操作习惯兼容。

## 3. 代码与模块边界

### 3.1 目录职责（必须）

- `src/gui/qt/`：Qt 窗口、对话框、代理和控件。
- `src/gui/common/`：不依赖具体 GUI 框架的共享 UI 逻辑。
- `src/gui/`：主题、字体、剪贴板和可编辑性等共享能力。
- `src/theme_tokens.py`：跨界面的基础设计令牌。
- `src/gui/theme.py`：Qt 主题映射、字号和 QSS。
- `src/gui/qt/icons.py`：图标的唯一业务入口。
- `src/gui/qt/tooltips.py`：解释性 Tooltip 的统一入口。

页面不应复制公共 QSS、颜色值、图标名称或 Tooltip 样式。可复用逻辑应下沉到与其职责匹配的公共模块。

### 3.2 Qt 枚举（必须）

PySide6 6.11 不再保证实例级枚举可用。必须使用类级枚举或 `Qt` 常量：

```python
QPainter.RenderHint.Antialiasing
```

禁止：

```python
painter.Antialiasing
```

## 4. 色彩系统

### 4.1 调色板（必须）

当前视觉体系由以下内容组成：

- 一套暖灰色中性色阶；
- 单一陶土色强调色 `#b5572f`；
- 颜色统一定义在 `src/theme_tokens.py` 和 `src/gui/theme.py`。

功能模块不得：

- 直接硬编码十六进制颜色；
- 引入第二种强调色，尤其是蓝色或青色；
- 为单个页面自行创建与全局主题无关的配色体系。

正文文字与背景的对比度必须不低于 4.5:1。调色板约束由 `tests/test_theme_qt.py` 部分覆盖。

### 4.2 语义色（规划中）

成功、警告、错误、信息等状态色需要统一定义后才能在业务页面中使用。在公共语义色令牌建立之前，不应在功能模块中临时硬编码红、黄、绿、蓝等颜色。

## 5. 字体与字号

### 5.1 唯一字号来源（必须）

字号只能通过以下入口获取：

- `theme.FONT_SIZE_MULTIPLIERS`
- `theme.font_px(role)`

QSS 中必须插入计算后的值：

```python
f"font-size: {font_px('small')}px;"
```

禁止直接写固定字号：

```css
font-size: 14px;
```

也禁止把 Python 调用原样放入 QSS：

```css
font-size: font_px('small');
```

相关约束由 `tests/test_font_consistency.py` 检查。

### 5.2 字体角色（必须）

新增控件应按语义选择既有角色，不得为单个页面创建近似字号：

| 角色 | 用途 | 默认字重 |
| --- | --- | --- |
| `title` | 页面或项目一级标题 | Bold |
| `heading` | 页面分区标题 | Bold |
| `subheading` | 卡片、小节三级标题 | Bold |
| `body` | 正文、输入和普通标签 | Regular |
| `body_bold` | 需要强调的正文 | Bold |
| `small` | 辅助说明和次要信息 | Regular |
| `button` / `dialog_btn` | 普通按钮和对话框按钮 | Bold |
| `tree` / `tree_header` | 表格内容和表头 | Regular / Bold |
| `amount` | 关键金额和大数字 | Bold |

Python 控件使用 `font_manager.get(role)`；QSS 使用 `font_px(role)`。字体设置预览和实际控件均使用 pixel size，不能用 `QFont(family, size)` 的 point size 构造方式混用单位。

默认情况下，同一界面应保持统一字体家族。按角色单独设置字体属于用户高级定制能力，业务代码不得利用它建立页面专属字体。

### 5.3 随字号缩放的布局（必须）

用于防止文本截断的尺寸必须随字号变化，例如表单标签列宽应使用 `label_col_width()`。不得以固定宽度假设所有用户都采用默认字号。

新增或调整固定宽高时，至少验证默认字号以及 18px、20px 基准字号；标题、金额、表格行和设置页导航不得因字号放大而裁切。

## 6. 图标

### 6.1 图标入口（必须）

所有图标必须通过 `src/gui/qt/icons.py` 获取。业务模块不得直接书写 qtawesome 图标名称。

当前使用 Phosphor `ph.*` 线性图标。qtawesome 1.4.2 不提供 `fa5r`，不得使用该前缀。

### 6.2 图标表现（必须）

- 禁止使用彩色 Emoji 作为按钮、菜单或状态图标。
- 同一动作应复用同一个公共图标定义。
- 图标不能成为关键操作含义的唯一载体；必要时配合文字或 Tooltip。

## 7. Tooltip

### 7.1 普通控件（必须）

解释性悬浮文本必须使用：

```python
set_readable_tooltip(widget, text)
```

不得在新增代码中直接调用 `widget.setToolTip()`。Tooltip 外观应为高对比度的深暖灰背景和浅色文字，颜色由公共模块统一控制。

### 7.2 Item View（必须）

无法安装控件过滤器的 item-view Tooltip 使用 `TOOLTIP_QSS` 作为回退。包含这类 Tooltip 的局部样式容器必须追加该公共 QSS，不得在页面内重新定义 Tooltip 颜色。

## 8. 表格与行级操作

### 8.1 悬停状态（必须）

行级 UI 不得仅依赖：

```python
option.state & QStyle.State_MouseOver
```

`QtBaseTable` 通过 `RowActionDelegate.set_hover_row()` 维护真实悬停行。操作按钮和行背景必须使用同一个 hover-row 状态，避免绘制错位。

### 8.2 信息密度（推荐）

- 重要业务字段优先展示，低频字段可通过列配置控制。
- 表头命名应简短且与业务术语一致。
- 数字、金额和日期在同一列中保持统一格式与对齐方式。
- 行级危险操作应有确认或可恢复机制。

## 9. 对话框

### 9.1 父级窗口（必须）

qfluentwidgets 的 `MessageBox` / `MaskDialogBase` 会按传入 parent 的尺寸创建遮罩。确认操作应优先使用项目的 `confirm_dialog()`，不得把狭窄侧边栏等子控件直接作为遮罩对话框的最终父级。

### 9.2 内容与按钮（推荐）

- 标题说明动作，正文说明影响。
- 主动作与取消动作的顺序在全应用保持一致。
- 删除、覆盖等不可逆动作应明确说明对象及后果。
- 按钮文案使用具体动词，避免仅写“是/否”。

## 10. 间距、圆角与控件尺寸

### 10.1 间距（推荐）

新增界面优先使用以下间距等级：

```text
4 / 8 / 12 / 16 / 24 / 32 px
```

同类容器使用一致的内边距；相关内容之间使用较小间距，不同信息组之间使用较大间距。

### 10.2 统一令牌（规划中）

间距、圆角、控件高度和边框宽度目前尚未完全令牌化。后续应建立统一常量并逐步替换散落的尺寸值。在公共令牌建立前，新页面应减少没有明确原因的任意尺寸。

## 11. 按钮和表单

### 11.1 按钮层级（推荐）

- 每个操作区域通常只保留一个视觉主按钮。
- 次要操作降低视觉权重，但仍需保持可发现性。
- 危险操作不得伪装成普通主操作。
- 同一页面中相同层级的按钮应保持高度、内边距和图标位置一致。

### 11.2 表单反馈（推荐）

- 标签靠近对应输入控件。
- 必填、格式和范围要求应在提交前或输入后及时反馈。
- 错误信息应说明如何修正，不能只改变边框颜色。
- 保存成功、保存失败和未保存状态应提供明确反馈。

## 12. 空状态、加载状态和错误状态

### 12.1 状态完整性（推荐）

新增数据页面应考虑：

- 首次使用的空状态；
- 搜索无结果状态；
- 数据加载中状态；
- 加载或保存失败状态；
- 权限或编辑状态限制。

空状态应说明当前情况，并在存在合理下一步时提供操作入口。

## 13. 键盘与可访问性

### 13.1 基础要求（推荐）

- 常用操作应能通过 Tab 顺序访问。
- 焦点状态必须清晰可见。
- 不以颜色作为状态区分的唯一方式。
- 图标按钮应具有可理解的名称或 Tooltip。
- 正文文本保持至少 4.5:1 的对比度。

## 14. 生命周期与异步任务

### 14.1 保存桥关闭（必须）

持有 `ProjectSaveBridge` 的宿主 `QObject` 在销毁前必须调用 `close()`。新增独立窗口或宿主对象时，应验证后台线程不会在 QObject 销毁后继续发出信号。

## 15. UI 变更验收清单

每次 UI 修改至少检查：

- [ ] 未在功能模块中硬编码颜色或固定字号。
- [ ] 图标来自 `src/gui/qt/icons.py`，且未使用彩色 Emoji。
- [ ] 新增解释性 Tooltip 使用 `set_readable_tooltip()`。
- [ ] 默认字号及放大字号下没有文本截断。
- [ ] 窗口缩放后布局和对话框显示正常。
- [ ] 表格滚动、悬停和行级操作状态一致。
- [ ] 保存、错误、空数据等相关状态具有明确反馈。
- [ ] 键盘焦点顺序和焦点样式可用。
- [ ] 关闭窗口时后台任务和保存桥正常结束。
- [ ] 运行编译检查和完整测试套件。

建议验证命令：

```powershell
.\.venv\Scripts\python.exe -m compileall -q main.py src
.\.venv\Scripts\python.exe -m unittest discover -s tests
```

GUI 改动还应手动验证启动、窗口缩放、数据持久化及相关对话框。涉及视觉调整的合并请求应附上截图。

## 16. 规范维护

新增公共组件、设计令牌或交互模式时，应同时完成：

1. 在公共模块中提供统一实现；
2. 更新本文档中的状态和使用示例；
3. 在 `AGENTS.md` 中保留必要的强制约束摘要；
4. 对容易回归的规则增加自动化测试；
5. 记录旧界面的迁移范围，避免新旧规范长期并存。
